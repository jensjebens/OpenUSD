# Derived-trim (pcurve-less) fixtures

Each `<name>NoPcurves.usda` here is generated from `../<name>.usda` by removing
the five `brep:curveUv:nurb:*` arrays and dropping the `BrepCurveUvNurbAPI`
applied schema. Face trims are therefore **derived from the 3D edge curves** at
read time instead of read from authored 2D pcurves.

## Why

`brep:curveUv` is **optional** in the UsdSolid proposal (#109): the 3D edge
curve is the model truth, and pcurves are a tessellation accelerant. Every
conformant consumer must handle both encodings, so this matrix pairs each
authored-pcurve original with its pcurve-less twin and checks that hdOcct
derives an equivalent trim from the 3D edges.

## Provenance

Generated by stripping `brep:curveUv:nurb:{controlVertices,vertexCount,order,knots,weights}`
and the `BrepCurveUvNurbAPI` schema from the originals in `../`. They validate
clean under `usdSolidValidators` (dropping the API avoids BA.415 "API applied
but no data").

## Acceptance

`testUsdSolidTessellation.py :: TestPcurveLessTwins` tessellates each twin and
checks the vertex count. The derived-trim mesh is coarser than the
authored-pcurve original for curved faces and identical for planar ones; holes
are cut correctly (cube/plane/depressed-plane holes present, matching extents).

## Known limitation

`testSphereNoPcurves` renders as **half** a sphere. `testSphere` is authored as
two seam-split half-lune faces; without pcurves the meridian-only boundary wire
cannot close a lune (the degenerate pole/seam edges are absent per rule 381).
This is an authoring-form limitation, not a general one — a sphere authored as a
single natural-bound face (`testAnalyticSphere`) renders correctly pcurve-less.
Tracked as `test_twin_Sphere_rendersFull` (an `expectedFailure`).
